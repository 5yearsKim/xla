# Workload rewrite validation

The default C++ definitions in `bridge/tensor_lang/tensor_rules.cc` now compile
49 directional rules: 13 generic property rules, 10 explicit dot-chain rules,
14 sum/dot rules, two direct LoRA rules, four coordinated kernel-attention
rules, two dot/division rules, two Gram-norm rules, and two opt-in centered-square
raw-moment rules. This replaces
`tensor.rules`, the text parser, file loading, and embedded rule generation.
The pattern API and optional checked C++ callbacks are described
in [TENSORLANG.md](TENSORLANG.md#c-pattern-definitions).

Small signature tables cover row sums, rank-4 spatial sums, transposed
keys, unbatched kernel denominators, and sums of rank-3 weights. LoRA can discover
`X(W + AB) = XW + (XA)B` in one match. Kernel attention can replace both consumers
of `Q'K'^T` with `K'^TV` and a key sum, while preserving the denominator's existing
broadcasts. It accepts explicit and folded key transposes. The feature map stays
opaque; these rules do not move through softmax.

The dot/division and Gram-norm rules keep the current C++ pattern API. Typed
`BroadcastAttrs` bindings capture the dimension mapping and destination type;
checked callbacks rebuild a broadcast at the dot output shape. No new semantic
operators, generic dimension solver, reduction-region representation, or egg-c
features were introduced.

`dot-divide-broadcast` moves row-wise division after a matrix/batch-matrix dot.
It recognizes direct and two-stage broadcasts, including singleton dimensions
mapped onto the contracted axis, and rejects denominators that vary along that
axis. It preserves precision and uses a floating-only numerical guard. Relaxed
mode enables its separate `rewrite_dot_division` permission; the CLI override
`--allow-dot-division=false` disables it. This assumes nonzero finite denominators
and acceptable intermediate range/rounding changes. A native stress test shows
why the permission matters: the unnormalized dot can overflow while the original
normalized dot is finite. This is normalization movement, not distributed
max/sum/value-summary merging or streaming attention.

`feature-gram-to-sample-gram` supports explicit and folded transposes for
`sum((A^T B)^2) = sum((AA^T) * (BB^T))`, with a common sample count and possibly
different feature counts. Float use is relaxed; modular integers are exact.
The isolated norm has no normalization factor or diagonal penalty to transform.
The full Barlow workload still retains its correlation matrix and gather boundary.

All dot equations infer complete replacement types, retain captured precision,
and use explicit numerical guards. Floating equations require relaxed dot
arithmetic, reassociation/distribution, finite-value, and signed-zero permissions.
They are approximate floating algebra, not bitwise equalities. Integer equations
use modular arithmetic. Nondefault precision, algorithms, unsupported metadata,
complex arithmetic, and invalid replacements are rejected. Generic Associative
continues to exclude DotGeneral.

## Checks completed on 2026-09-28

The full Bazel suite passed all 21 test targets. Native tests include independent
modular-integer and floating interpreters for matrix chains and sum/dot equations,
precision/policy rejection, callback validation, and invalid-RHS nonmutation.
Broadcast tests cover 16 direct/nested scalar, row, per-query, and batched maps,
including singleton contracting dimensions and preservation of DEFAULT precision.
Gram tests independently evaluate rectangular floating and modular integer cases.

The Python suite passed all 18 tests, including the original independent NumPy
references, directional gradient checks, numerical stress cases, and CLI lowering.
The integration suite exercised 109 programs:

- 74 forward programs: all 12 registered workloads (including MegatronLayer),
  every input layout, and both strict and relaxed policies.
- Eight dimension controls for reduce-dot, LoRA, graph convolution, and kernel
  attention, including dimensions that reverse intermediate-size advantages.
- Eleven relaxed backward programs generated by JAX from the original workloads.
- Four attention dimension/permission controls: sequence width 8 versus value
  widths 4 and 16, with dot division enabled and disabled. The selected output
  is divide-after-dot only for the smaller output width when permission is enabled.
- Twelve standalone Gram-norm programs: three sample/feature shape combinations,
  forward and backward, in strict and relaxed modes. Relaxed forward selects
  sample matrices for `(N,Da,Db)=(4,16,16)` and `(4,8,12)`, and retains the feature
  cross-product for `(16,4,4)`. All Gram forward searches saturate. Gradients are
  compared against JAX differentiation of the independent sample-Gram formula.

Workloads and standalone controls were lowered through JAX, passed through the
C++ engine and MLIR verification, then compiled and executed on CPU. Forward
values were compared to independent NumPy references (Megatron uses the original
JAX program); backward values were compared to the original JAX gradients.
Integer outputs were checked exactly; floating tolerances were 3e-5 forward and
3e-4 backward. For this numerical execution only, mesh and argument placement
annotations were removed and full inputs were executed on one CPU. The engine
itself processed and verified the original four-device mesh/annotations.
These checks do not measure accelerator latency or collective traffic.

The subsequent four-arm experiment adds 24 cases across reduce-dot, dense graph
convolution, kernel linear attention, and LayerNorm, plus six LayerNorm flag-off
controls. Every selected arm's arithmetic and original backward programs pass
numerical checks. See [the experiment report](results/four_arm/REPORT.md) for
costs, collective counts, layout adapters, bounded-search limitations, and the
aggressive variance stress result.

The named target rules applied in every tested layout for reduce-dot, LoRA,
graph convolution, kernel attention, and context attention. Shape-control tests
check the emitted intermediates, not merely rule match counters. The reversed LoRA, graph, and
kernel dimensions select the original matrix-chain form under the compute cost.
Layout tests check correctness and rule availability; they do not establish a
sharding-dependent communication improvement.

Across the 109 programs there were 141 rewrite sessions: 134 saturated, six reached
the iteration limit, and one reached the match limit. All selected outputs were
valid and numerically passed. Kernel-attention limits include its backward
program. Generic distribution/association over positive feature-map additions
expands many equivalent expressions; the existing bounded search and extraction
fallbacks remain in effect. Saturation and DAG optimality are not claimed for
these limited runs.

## Intentionally omitted

- **Distributed vocabulary CE and softmax attention:** these need block/local
  summary construction and collective-aware lowering. The current algebraic
  node language does not model those summaries or communication operations.
- **Custom distributed LayerNorm summaries:** no new local-statistics or
  collective pattern is introduced. The implemented centered-square raw-moment
  equation exposes two ordinary sum reductions, and Shardy supplies distributed
  lowering. It requires the separate `--allow-raw-moments` permission, disabled
  even in relaxed mode. Canonical direct and JAX keepdims mean broadcasts are
  supported; wrong divisors, invalid broadcasts, and strict/default permissions
  are rejected. A large-offset input demonstrates variance collapsing to zero.
- **Full Barlow sample-Gram loss:** gather is a preserved boundary, and contiguous
  rewrite islands separate correlation formation from its later squared-norm
  consumer. The Gram identity also needs an independent diagonal computation to
  eliminate the full correlation. The implemented isolated norm rule does not make
  this actual workload avoid its feature matrix.
- **Hierarchical MoE top-k:** top-k/gather admission, global IDs, deterministic
  tie semantics, and full-softmax denominator handling need more importer and
  engine support.
- **QKV/gated-MLP projection fusion:** constructing and slicing combined outputs
  needs additional concatenate/slice patterns and multi-output coordination.
  These remain controls because backend fusion may already cover the benefit.

The Python originals have not been modified to embed optimized alternatives.
No general dimension solver, sparse GCN importer, or new egg-c language feature
was added for these workloads.

## Reproduce

From the XLA root:

```sh
bazel build --config=joint_shard //research/joint_shard/tools:parse_stablehlo
bazel test --config=joint_shard //research/joint_shard:tests --test_output=errors
```

From `research/joint_shard_python`:

```sh
JOINT_SHARD_REWRITE_REPORT_DIR=/tmp/joint_shard_workload_validation \
  uv run python -m unittest discover -s tests -p test_rewrite_saturation.py -v
uv run python -m unittest discover -s tests -v
```

The integration tests skip when the default binary has not been built. Set
`JOINT_SHARD_REWRITE_BINARY` to test another build; an invalid explicit path fails.
The optional report directory retains original/replacement MLIR, per-program
rewrite diagnostics, and `summary.json` containing dimensions, layouts, stop
reasons, applied rules, boundaries, and selected dot shapes. Results depend on
input dimensions and the configured search/extraction budgets.
